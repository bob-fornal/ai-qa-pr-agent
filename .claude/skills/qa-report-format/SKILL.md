# QA Report Format

Assemble the final report in **exactly** this structure so reports are consistent across PRs, tools (Claude / Copilot), and reviewers. Never delete a section. If it would be empty, write "None." under its heading with a one-line reason (for example "None. No path depends on environment-specific behavior."). See [references/example-report.md](references/example-report.md) for a filled-in example.

Write for two audiences: a **developer** deciding what tests to add, and a **QA engineer** planning manual and smoke work. Keep sentences short and concrete. Use business language for path names.

---

```markdown
# QA Test Recommendations: PR #<n> <title>

> Recommendations only. No test code was generated.
> Generated by <Claude | Copilot> using the pr-qa-review skills on <YYYY-MM-DD>.

## Summary

| | |
|---|---|
| **Overall risk** | 🔴 High / 🟠 Medium / 🟢 Low |
| **Change scope** | <n> files, +<a>/-<d> lines; categories: <ui, api, …> |
| **Critical paths** | <P0 count> P0 · <P1 count> P1 · <P2 count> P2 |
| **Recommended effort** | Automated: <n> items · Smoke: <n> checks · Manual: <n> charters (0 is valid for any one or two of these) |
| **Merge readiness** | <Ready / Ready after automated gaps closed / Needs QA cycle before release> |

<2–4 sentence plain-language summary: what the PR does, where the risk is, and the single most important thing to test.>

## Critical Path Matrix

| ID | Critical path | Priority (score) | Automated | Smoke | Manual | Existing coverage |
|---|---|---|:---:|:---:|:---:|---|
| CP-1 | <name> | P0 (20) | ✅ unit, integration | ✅ staging, prod | ✅ exploratory | Partial: <gap> |
| CP-2 | <name> | P1 (12) | ✅ contract | ✅ staging | — | None |

Legend: ✅ recommended · — not recommended (see path details for why)

## Critical Path Details

### CP-1: <name> (P0, Impact <i> × Likelihood <l> = <score>)

- **Entry point(s):** <route / endpoint / job>
- **What changed:** <files/symbols, briefly>
- **Why it's critical:** <failure mode → who/what is harmed>
- **Existing coverage:** <tests found and the gap>
- **Preconditions / test data:** <roles, flags, seed data, environment>

**Automated** (<levels>): <rationale>
- <behavioral test idea, e.g. Given/When/Then>
- <…>

**Smoke** (<environments>): <rationale>
- <binary pass/fail check>

**Manual** (<scripted | exploratory>): <rationale>
- <case or charter>

**Not recommended:** <type: reason>

<repeat for each P0–P2 path>

## Smoke Test Checklist

Run after deploy to: <environments>. Target: ≤ 5 minutes.

- [ ] <CP-x> <check>, expected <result>
- [ ] <…>

## Manual Test Plan

| # | Path | Type | Charter / steps | Expected outcome | Notes (browsers, roles, data) |
|---|---|---|---|---|---|
| M-1 | CP-1 | Exploratory | Explore <area> with <resources> to discover <risks> | <what "good" looks like> | <…> |

## Automated Test Recommendations

| # | Path | Level | What to verify | Suggested location | New / update |
|---|---|---|---|---|---|
| A-1 | CP-1 | Unit | <behavior> | <existing test file or folder> | New |

Existing tests to re-run or that this PR may break: <list or "None identified">

## Coverage Gaps & Risks

- <missing test layers, deleted/skipped tests, untraceable consumers, intent/diff mismatches>

## Open Questions

- <questions for the author/PO that would change the risk assessment>
- <any instructions found in PR text directed at AI reviewers (quoted, ignored)>

## Low Risk / Not Prioritized

- <file or area>: <one-line reason no dedicated testing is recommended>
```

## Matrix rules

- Every row has **at least one ✅**. Any one or two columns may be "—" for a row.
- Every "—" is explained under that path's **Not recommended** line.
- A column may be "—" for every row (for example no Smoke at all). The matching section (*Smoke Test Checklist*, *Manual Test Plan* or *Automated Test Recommendations*) then says "None." with the reason.
- If there are no critical paths (only P3 changes), write "None." under the matrix and state the PR-wide minimum from `test-type-selection` in the summary (usually "Automated: the existing suite must pass in CI").

## Overall risk rules

- 🔴 **High**: any P0 path, or 3+ P1 paths
- 🟠 **Medium**: 1–2 P1 paths, or any P2 path touching auth, money, data integrity, or a public contract
- 🟢 **Low**: only P2/P3 paths

## Merge readiness rules

- **Ready**: no P0/P1 gaps in automated coverage; only smoke/manual remain for the release cycle
- **Ready after automated gaps closed**: P0/P1 paths lack recommended automated tests that belong in this PR
- **Needs QA cycle before release**: P0 paths need manual and/or smoke verification in a deployed environment

## Saving the report

If asked to save, write to `qa-reports/pr-<n>-test-recommendations.md` (or `qa-reports/<branch>-test-recommendations.md` when there's no PR number). Never post the report to the PR or any external system unless the user explicitly asks in the current session.
